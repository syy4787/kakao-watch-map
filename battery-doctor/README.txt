워치9 배터리 닥터 (battery-doctor) — Windows PC 툴킷
=====================================================

이게 뭔가요
-----------
갤럭시 워치9의 배터리가 비정상적으로 빨리 닳을 때, 루트 없이 PC에서 ADB(무선 디버깅)로
워치의 배터리 통계(dumpsys)와 워치 앱(갤럭시워치 전용앱)이 15분마다 남긴 배터리 기록(CSV)을
가져와서 원인을 숫자로 판정하고(잔량 표시 오류 / 소프트웨어 과소모 / 사용 패턴 / 하드웨어 의심 / 정상),
ADB로만 바꿀 수 있는 차단 조치를 골라 적용·되돌리고, 서비스센터·삼성멤버스·소비자원에 낼
증거 패키지(보고서·원자료·신고문 3종)를 만듭니다.

네트워크를 쓰지 않습니다(adb 가 없을 때 물어본 뒤 구글에서 한 번 받는 것만 빼고). 모든 결과는 이 폴더의 data\ 안에만 남습니다.

준비물
------
1. 따로 설치할 것은 없습니다. zip 을 '압축 풀기(모두 추출)'로 통째로 풀어 runtime 폴더가 BatteryDoctor.bat 옆에 있게 하세요.
   - Java: runtime\ 에 함께 들어 있습니다 (Eclipse Temurin 21 JRE 그대로 — GPLv2+Classpath Exception, runtime\legal\ 참고).
     zip 을 풀지 않고 탐색기 안에서 바로 .bat 을 실행하면 runtime 이 없어 'java.exe not found' 가 납니다.
   - adb : Android Studio 의 것(%LOCALAPPDATA%\Android\Sdk\platform-tools)이나 PATH 의 adb 를 알아서 찾고,
     어디에도 없으면 워치와 하는 메뉴(1 연결 등)를 처음 고를 때 물어본 뒤 구글 공식 주소에서 Android SDK Platform-Tools(약 8MB)를 받아
     이 폴더의 platform-tools\ 에 둡니다(구글 라이선스에 동의해야 함 — 라이선스 때문에 zip 에는 넣지 않았습니다).
     직접 깔려면 https://developer.android.com/studio/releases/platform-tools 에서 Windows 용 zip 을 받아
     그 안의 platform-tools 폴더를 이 폴더에 두면 됩니다.
2. 워치와 PC가 같은 Wi-Fi에 있어야 합니다. 손님용 Wi-Fi·AP 격리(기기 간 통신 차단)가 켜진 공유기는 안 됩니다.
   안 되면 휴대폰 핫스팟에 PC와 워치를 함께 붙이세요.
3. 워치의 전용앱에서 '배터리' 화면을 한 번 열어 두면 15분마다 기록이 쌓입니다 (없어도 dumpsys만으로 분석은 되지만 신뢰도가 한 단계 낮습니다).

워치에서 무선 디버깅 켜기 (처음 한 번)
--------------------------------------
1) 워치: 설정 > 워치 정보 > 소프트웨어 > '소프트웨어 버전'을 5번 연속 탭 → 개발자 모드가 켜집니다
2) 워치: 설정 > 개발자 옵션 > 'ADB 디버깅' 켜기, '무선 디버깅' 켜기 ("이 네트워크에서 항상 허용")
   연결 작업 중에는 '자동 Wi-Fi 끄기'도 켜 두면 끊김이 줄어듭니다. 측정을 시작하면 다시 끄세요(측정이 오염됩니다).
3) 무선 디버깅 > '새 기기 페어링' → 화면의 IP:페어링포트 와 6자리 코드를 메뉴 1에서 입력
4) 그다음 무선 디버깅 화면 첫 줄의 IP:연결포트 를 입력 (페어링 포트와 '다른' 번호입니다)
   무선 디버깅을 껐다 켜거나 Wi-Fi가 바뀌면 포트가 바뀝니다. 그때는 메뉴 1을 다시 실행하세요(페어링은 다시 안 해도 됨).
   워치 화면에 '이 컴퓨터에서 항상 허용' 안내가 뜨면 허용하세요.

실행
----
BatteryDoctor.bat 을 더블클릭하면 메뉴가 뜹니다. (명령 프롬프트에서 "BatteryDoctor.bat connect" 처럼 하위 명령도 됩니다)

  1 연결        워치와 무선 디버깅으로 연결 (처음이면 페어링 안내)           = connect [ip:port]
  2 수집·분석   dumpsys·워치 기록을 가져와 보고서(report.html)를 만들고 엽니다  = collect [--bugreport]
  3 측정 시작   배터리 통계 초기화 — 깨끗한 측정 구간 시작                     = reset
  4 차단 조치   추천 조치를 골라 적용 (모두 기록되고 되돌릴 수 있음)            = fix [--apply id,id] [--yes]
  5 되돌리기    적용한 조치를 역순으로 복구                                   = undo [--all | 번호]
  6 증거 패키지 보고서·원자료·신고문 3종 + 공유용 마스킹본(share\) + zip         = evidence [--purchase yyyy-MM-dd]
  7 권한 주기   워치 앱(배터리 지킴이)에 특수 권한 주기 (기록되고 되돌릴 수 있음)    = grant
  8 자동 치료   권한 → 수집·분석 → 조치 자동 적용 → 측정 시작까지 한 번에         = treat [--strong] [--yes] [--no-grant] [--bugreport]
  0 종료

  analyze [스냅샷 폴더]  — 마지막(또는 지정한) 스냅샷을 다시 분석만 합니다.

고를 것 없이 한 번에 끝내고 싶으면 메뉴 1(연결) 뒤 메뉴 8(자동 치료)만 실행하면 됩니다. 아래 '7 권한 주기 / 8 자동 치료' 참고.

측정 절차 (권장)
---------------
1. 메뉴 1 로 연결 → 메뉴 2 로 첫 수집 (지금 상태 기록).
2. 메뉴 3 '측정 시작' → 워치 개발자 옵션의 '자동 Wi-Fi 끄기'를 다시 끄고, 충전기에서 내려
   평소처럼 쓰거나(8시간 이상, 가능하면 밤사이 포함) 워치 배터리 화면의 '실험 시작'으로
   비행기 모드 / 절전 모드 / 시계만 사용 모드를 재세요.
3. 충전기에 올리기 '전에' 워치 Wi-Fi를 켜고 메뉴 2 '수집·분석'. (충전을 시작하면 '마지막 충전 이후' 통계가 섞입니다)
4. 보고서의 '지금 할 일 3가지'를 따릅니다. 소프트웨어 원인이면 메뉴 4 → 메뉴 3 → 24시간 뒤 메뉴 2 로 비교.
   (메뉴 8 '자동 치료'는 이 2~4단계를 고를 것 없이 한 번에 합니다.) 효과가 없으면 메뉴 5 로 되돌리고 다음 후보를 시도합니다.
5. 서비스센터·삼성멤버스에 갈 때 메뉴 6 으로 증거 패키지를 만듭니다. 구입일을 넣으면(--purchase)
   소비자분쟁해결기준의 어느 단계인지(10일 이내 / 1개월 이내 / 그 이후) 계산해 줍니다.

판정 기준 (보고서에 출처와 함께 표시)
------------------------------------
- 대기(화면 꺼짐) 소모: 시간당 3.2% 이하 정상 / 4.44% 초과 비정상 (Android vitals 워치페이스 기준)
- 24시간 평균: 3.3% 이하 정상 / 5.0% 이상 비정상 (공식 30~40시간에서 역산)
- 실험(비행기·절전·시계만): 1% 이하 정상 / 2% 초과 비정상 (경험칙)
- 앱 웨이크락: 시간당 18.5초 초과 주의, 합계 1시간 초과 비정상 (Android vitals) / 화면 꺼짐 중 깨어 있던 비율 10%·20% (경험칙)
- 잔량 표시 점검: 워치가 쉬는 동안(화면 꺼짐·충전 안 함) 잰 전압으로 어림잡은 잔량과 표시 잔량의 차이 — 12포인트 이상 의심, 20포인트 이상 확실
  ("17%에서 꺼졌다 켜니 47%"의 정체 = 게이지가 낮게 센 가짜 소모. 강제 재시작과 워치 배터리 화면의 '게이지 보정 시작'으로 다시 맞춥니다)
- Google Play 서비스: 추정 전력의 15% 이상이면 2026년 과소모 패턴 — 자동 치료가 모든 앱 캐시 정리(pm trim-caches, 데이터·로그인 그대로)와
  Play 서비스 다시 시작(am force-stop, 시스템이 곧바로 다시 띄움)을 함께 합니다. 둘 다 되돌릴 것 없는 일회성 조치입니다.
- 퍼센트 기준이라 40mm(390mAh)도 같은 표를 씁니다.

data\ 폴더에 무엇이 생기나
-------------------------
  data\config.properties            마지막 연결 주소, 구입일
  data\snapshots\yyyyMMdd-HHmmss\   수집 한 번 = 폴더 하나 (getprop·battery·batterystats·alarm·sensorservice… 텍스트, watch_log.csv, report.html)
  data\journal.jsonl                적용한 조치·준 권한과 이전 값 (되돌리기의 근거)
  data\evidence\yyyyMMdd\           증거 패키지 (report.html, summary.json, watch_log.csv, snapshot\, 신고문 3종, share\) 와 같은 이름의 .zip

개인정보 — 꼭 읽어 주세요
------------------------
수집 원본(data\snapshots, data\evidence\...\snapshot)에는 일련번호, Wi-Fi 이름, 위치 기록, 계정 이메일 같은
개인정보가 들어 있을 수 있습니다. 서비스센터·삼성멤버스에 낼 때만 원본을 쓰세요.
다른 사람(커뮤니티, 채팅, AI 도우미 등)에게 보낼 때는 증거 패키지 안의 share\ 폴더만 쓰세요.
share\ 는 이메일·전화번호·좌표·일련번호·Wi-Fi 이름·기기 이름을 마스킹하고 위치 덤프(location)를 통째로 뺀 사본입니다.
정규식 기반이라 완벽하지 않으니 올리기 전에 한 번 훑어보세요.

차단 조치 등급
-------------
  안전  설정 변경(Wi-Fi/BLE 스캔 끄기, 적응형 배터리 켜기, 화면 자동 꺼짐), 안 쓰는 앱 비활성화, 통계 초기화 — 기능 손실 거의 없음
  주의  백그라운드 실행 제한, 대기 버킷 restricted, Doze 예외 해제, 강제 종료, AOD 끄기 — 알림·동기화가 늦어질 수 있음, 되돌리기 가능
  강함  Play 서비스/시스템 앱 업데이트 제거, 앱 데이터 삭제, 재시작 — 기본 꺼짐, 적용 전 한 번 더 확인, 일부는 되돌릴 수 없음
핵심 시스템(Play 서비스, Samsung Health, 시스템 UI, 설정, 전화, 블루투스, Galaxy Wearable 연결 등)은 비활성화·데이터 삭제 대상에서 제외됩니다.

7 권한 주기 / 8 자동 치료
-------------------------
메뉴 7(= grant)은 워치 앱(갤럭시워치 전용앱 v2.33 이상)에 들어 있는 '배터리 지킴이'가 쓸 특수 권한을 줍니다.
일반 앱은 스스로 받을 수 없고 PC 의 adb 로만 줄 수 있는 권한이라, PC 에서 한 번만 해 주면 됩니다.
  BATTERY_STATS, GET_USAGE_STATS      앱별 배터리 소모와 사용 통계를 워치 화면에서 바로 보기
  WRITE_SECURE_SETTINGS, WRITE_SETTINGS  절전 모드·AOD·위치·동기화(와 화면 밝기·꺼짐 시간)를 지킴이가 상황에 맞춰 자동 조절
  DUMP, READ_LOGS                     웨이크락·알람 같은 시스템 상태와 로그를 읽어 범인 앱 찾기
권한마다 성공/실패(사유)를 표로 보여 줍니다.
  "앱이 아직 설치되지 않았습니다"  → 워치 앱을 v2.33 이상으로 업데이트(설치)한 뒤 다시 실행
  "앱 버전이 낮아 … 요청하지 않습니다" → 워치 앱을 업데이트한 뒤 다시 실행
  "이 펌웨어가 막았습니다"          → 그 기능만 지킴이 화면에 '권한 없음'으로 표시되고 나머지는 그대로 됩니다
준 권한은 모두 data\journal.jsonl 에 기록되며, 메뉴 5 → all (= undo --all) 로 전부 회수(revoke)됩니다.

메뉴 8(= treat)은 고를 것 없이 한 번에 합니다: 권한 주기 → 수집·분석(메뉴 2 와 같음) → 조치 자동 적용 → 측정 시작(통계 초기화).
자동으로 적용하는 것은 다음뿐입니다.
  - '안전' 등급 중 추천된 것과 손실 없는 설정 4가지(Wi-Fi/BLE 스캔 끄기, 적응형 배터리·앱 대기 켜기) — 현재 값이 목표와 다를 때만
  - 분석이 범인으로 지목한 앱에 추천된 '주의' 조치(백그라운드 실행 제한, 대기 버킷 restricted, Doze 예외 해제)
AOD 끄기, 전용앱·Samsung Health 관련 조치, '강함' 등급은 자동으로 하지 않습니다. 강함 등급은 treat --strong 을 붙였을 때만
후보에 넣고 항목마다 yes 를 물어봅니다(--yes 를 붙이면 묻지 않음). 이미 목표 상태인 조치는 건너뜁니다.
끝나면 적용한 조치(이전 값 → 새 값), 건너뛴 추천과 이유, 범인 앱, 보고서 경로를 요약합니다. 24시간 뒤 메뉴 2 로 비교하세요.
두 번째 수집부터는 '지난 수집과 비교'가 저절로 나옵니다 — 전체·화면 꺼짐 소모, 깨어 있던 비율, Play 서비스 몫, 워치 앱의 대기·밤사이 소모와
금방 꺼진 화면을 지난번과 나란히 놓고 '좋아짐·비슷·나빠짐'과 그 사이에 한 조치를 보여 줍니다(보고서의 '치료 전후 비교').
  옵션: --strong (강함 등급 후보 포함)  --yes (강함 확인 생략)  --no-grant (권한 주기 생략)  --bugreport (bugreport 도 수집)
모든 조치는 메뉴 4 와 같은 경로로 기록되므로 메뉴 5(되돌리기) → all 로 역순 복구되며, 그때 권한도 함께 회수됩니다.

문제가 생기면
------------
- "연결된 워치가 없습니다": 메뉴 1 을 다시 실행. 워치 화면을 켠 채로, 무선 디버깅 화면의 IP:연결포트를 확인.
- 기기가 offline: 워치의 무선 디버깅을 껐다 켜고, 명령 프롬프트에서 adb kill-server 후 다시 시도.
  (adb 를 이 폴더에 받았으면 명령 프롬프트에서 이 폴더로 가서 platform-tools\adb kill-server)
- "java.exe not found": zip 을 통째로 다시 풀어 runtime 폴더가 .bat 옆에 있게 하세요.
- adb 를 받지 못했으면(회사·학교망, 백신): 위 '준비물'의 주소에서 직접 받아 platform-tools 폴더를 이 폴더에 두세요.
- 보고서가 자동으로 안 열리면 표시된 경로의 report.html 을 더블클릭하세요.
- 강제 재시작: 홈 + 뒤로 가기 버튼을 꺼질 때까지(7초 이상), 효과 없으면 30초까지.
