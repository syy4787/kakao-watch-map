# 갤럭시워치 전용앱 — 카카오맵 길찾기 + 유튜브 (Wear OS)

갤럭시 워치9 44mm(1.47″ 480×480 원형)에 맞춘 **걷기·대중교통·자전거 길찾기 전용** 지도 앱입니다.
자동차 길찾기는 넣지 않았습니다. 카카오맵 앱의 길찾기 흐름(도착지 검색 → 이동수단 탭 → 경로 목록 → 상세 → 지도에서 안내)을 워치 화면에 맞게 옮겼습니다.
아이콘·로고·화면 디자인은 카카오 것을 베끼지 않고 Material 아이콘으로 새로 만들었습니다.

## 기능

| 화면 | 하는 일 |
|---|---|
| **첫 화면** | 워치 앱 목록의 아이콘은 **갤럭시워치 전용앱** 하나. 누르면 큰 동그라미 두 개 — **카카오맵**(길찾기·버스) / **유튜브**(동영상·음악·구독) — 중에 고른다. 고른 앱에서 뒤로 가면 워치 화면으로 — 지도는 닫히지 않고 뒤로 가 있다가, 첫 화면에서 다시 고르면 **보던 그대로**(안내 중이던 지도·타일로 연 검색 화면 등, 새로 띄우지 않아 바로 뜸). 아래에 **업데이트** 버튼(새 버전이 있으면 파랗게)과 동그란 **배터리** 버튼(배터리 기록·판정 화면, 뒤로 가면 고르는 화면) |
| **지도** | 원 전체를 지도가 채움. 카카오 로고는 원 안 위쪽으로 옮김(가리면 안 됨). 원 테두리를 따라 길찾기·확대·내 위치·축소 버튼이 놓이고, **내 위치 버튼은 카카오맵처럼 늘 보임**(지도를 끌어 옮겼다가 바로 내 위치로) — 나머지는 4초 뒤 숨고 지도를 톡 치면 다시 나타남. 경로를 띄운 동안엔 버튼이 안내를 가리지 않게 3시 ✕(안내 종료)·9시 내 위치만 |
| 베젤·크라운 | 시계 방향 = 확대, 반대 = 축소 |
| 내 위치 버튼 | 한 번 = **내가 보는 쪽이 위**(지도가 내 방향으로 돌고 파란 부채꼴은 늘 위 = 앞 — 처음 열 때 기본), 두 번 = 북쪽이 위(부채꼴은 지도 위의 방위라 북쪽을 볼 때만 앞을 가리킴), 세 번 = 끄기. 내가 보는 앞 = 화면 12시 쪽(오른손목에 버튼이 오른쪽으로 오게 찬 그대로 — 버튼 쪽도 그 반대도 아님). 지도가 정말 그쪽으로 도는지 화면 좌표로 확인해 반대면 스스로 고친다. 지도를 손으로 끌면 따라가기가 풀리고, 안내 중이면 손을 뗀 뒤 8초(또는 손목을 다시 올리면 바로) 다시 따라감 |
| **도착지 검색** | 음성·키보드·손글씨로 검색(카카오 장소 검색), 최근 목적지 10개. **내 근처부터** 찾음(최근 위치가 없으면 Wi-Fi·기지국으로 몇 초 잡아 보고, 그래도 없으면 전국에서 찾았다고 알림). **내 주변**: 편의점 · 약국 · 화장실 · 카페 · 지하철역을 5km 안 가까운 순으로(지금 위치로만 — 10분 넘은 위치면 새로 잡고, 못 잡으면 '위치를 잡지 못했어요'). 뒤로·오른쪽으로 쓸기는 **한 화면씩**(메뉴 → 결과 → 첫 화면 → 닫기), 결과로 돌아오면 보던 자리 그대로 |
| **집·회사** | 카카오맵처럼 검색 첫 화면에 집·회사 바로가기. 등록 안 됐으면 톡 → 검색해서 등록, 등록됐으면 톡 한 번에 길찾기(배너에 '→ 집'). 최근 목적지·검색 결과를 **길게 누르면** 집·회사로 등록, 등록된 집·회사를 길게 누르면 바꾸기·지우기 |
| **타일** | 워치 화면을 옆으로 넘기면 나오는 카드 '길찾기 바로가기': 집 · 회사 · 검색 버튼. 추가: 타일 화면을 길게 누름 → ＋ → 길찾기 바로가기. 집·회사를 바꿀 때만 다시 그려서 배터리를 쓰지 않음 |
| **길찾기** | 위쪽 탭: 대중교통 · 도보 · 자전거 (마지막에 고른 탭 기억). 카카오맵처럼 탭 아이콘 아래에 **걸리는 시간**, 세 수단 중 **가장 빨리 도착하는 수단은 초록**. 보고 있는 탭을 먼저 찾고 나머지 탭은 뒤이어 받음(직선 거리로 도보 15km·자전거 50km 가 넘으면 그 탭을 열 때만) |
| 대중교통 | 경로 카드마다 소요 시간·도착 예정 시각·요금·환승 횟수·도보 시간·구간 막대(노선 색). 첫 탈 것이 버스면 그 버스의 **실시간 도착**(공공데이터 키가 있을 때, 카카오맵 표기 `311번 3분 (2번째 전) · 다음 14분`, 아무 버스나 타도 되는 구간은 `105 곧 도착 · 115 7분`) — 목록을 보는 동안 45초마다 새로, 같은 정류장은 한 번만 물음. 여러 노선 중 아무거나 타도 되는 구간은 카카오맵처럼 `105외 5대`, 거리 따라 달라지는 요금은 `1,500~2,800원`. 가장 빨리 도착하는 경로에 **가장 빠름** 표시, 처음엔 **최소시간** 순(가장 빠른 경로가 맨 위). 위쪽 칩 두 개를 톡 하면 카카오맵처럼 **전체·버스·지하철·버스+지하철**로 거르고(있는 종류만, 개수 표시) **최소시간·최소환승·최소도보·추천순**(카카오가 준 순서 그대로)으로 정렬(정렬은 기억). 정류장까지 걷는 동안 먼저 떠날 버스는 `106번 3분 (2번째 전) · 놓칠 수 있어요 · 다음 15분`처럼 **탈 수 있는 다음 버스**까지. 카드의 '오후 3:48 도착'은 보고 있는 동안 **1분마다 지금 시각으로**(도보·자전거 카드도), 긴 요금·환승 줄은 두 줄로 |
| **기차·고속·시외버스** | 먼 곳(직선 25km 넘게)이면 카카오맵처럼 **열차(KTX·SRT·ITX·무궁화)·고속버스·시외버스** 경로도 함께 (카카오 대중교통 API는 대전→서울도 시외·직행버스 갈아타기 3시간짜리만 줌). 출발지·도착지 근처 역(가장 가까운 역 + 가장 가까운 KTX 역 + 근처 큰 역)과 터미널을 카카오 장소 검색으로 찾고, 공공데이터(TAGO) 오늘 시간표를 받아, 역까지·역에서 목적지까지는 카카오 대중교통(700m 안은 도보)으로 이어 한 경로로. 카드엔 `KTX 105 09:58 출발 · 대전역`, 거르기 칩에 **열차·고속버스·시외버스**. 시내 경로를 먼저 보여 주고 시간표 경로는 오는 대로 뒤에 붙임(최대 20초). 시간표 경로는 도착 시각이 정해져 있어 볼 때마다 남은 시간이 줄고, 나가야 할 시각이 지난 편은 빠짐(그 종류가 다 지나가면 다음 편을 다시 찾음, 5분에 한 번까지). TAGO 오늘 자료에 KTX 가 통째로 빠진 날(2026-10-13 대전→서울 실제로 28편 중 KTX 2편)은 다음 주 같은 요일 시간표로 채우고 목록·상세에 그렇다고 적음. 역·터미널 목록은 워치에 30일 저장. 밤 12시~새벽 4시엔 전날 시간표의 늦은 편도 봄. 역까지(역에서) 가는 길을 못 받으면 한 번 더 묻고, 그래도 못 받으면 어느 구간을 못 받았는지 목록 아래에 적고 **다시 찾기** |
| 경로 상세 | 출발 → 도보 → 버스(승차 정류장, 정거장 수, 하차 정류장, 탈 수 있는 버스 번호 전부, 실시간 도착 30초마다 갱신) → 지하철 → … → 도착. 기차·고속버스는 `[KTX-산천 105] 09:58 출발 / 대전역 승차 · 53분 / 서울역 10:51 도착` (실시간 버스는 기차를 타러 가는 버스만) |
| 도보·자전거 | 카카오맵과 같은 **경로 옵션 3가지**를 한꺼번에 찾아 카드로: 자전거 **자전거도로 우선**(조금 돌아가도 자전거도로로) · **최단 거리** · **편안한 길**(심한 경사·계단을 피한 넓은 길), 도보 **큰길 우선** · **최단 거리** · **편안한 길**. 카드마다 시간·거리·도착 시각, 가장 빨리 도착하는 카드에 **가장 빠름**, 같은 길이 나온 옵션은 한 카드로 합침. 처음엔 가장 빠른 길이 골라져 있고, 다른 카드를 누르면 그 옵션을 다음 길찾기에서도 먼저 고름('가장 빠름' 카드를 누르면 다시 늘 가장 빠른 길). 고른 길의 갈림길 안내 목록, **안내 시작** / **지도에서 보기**. 경로를 벗어나 재탐색할 때도 고른 옵션 그대로 |
| **안내 배너** | 카카오맵 길안내처럼 왼쪽에 회전 화살표(또는 버스·지하철 아이콘)와 그 아래 거리, 오른쪽에 짧은 할 일과 장소 하나: `[↰ 35m] 좌회전 / 역전약국 앞`, `[🚌 171m] 617번 승차 / 시청역`, `[🚌 1.2km] 617번 타는 중 / 은하수네거리 하차`. 글자 폭만큼만 차지하고 살짝 투명. 긴 이름은 글자를 조금 줄여 잘리지 않게. 톡 하면 둘째 줄 접기. 아래엔 한 줄 알약 `8.3km · 14:52 도착` (톡 → 경로 상세) |
| **정류장 수** | 버스·지하철을 타는 동안 카카오맵 알림("정류장 3개(7분)")처럼 `[🚇 3.4km] 3정거장 · 7분 / 정부청사 하차` (남은 시간 = 구간 소요 시간 × 남은 거리 비율, 정류장 위치를 모르면 `7분 후 하차`), 다음 정류장이 내릴 곳이면 "다음 정류장 하차" + 하차 진동 (카카오맵처럼). 지하철역 위치는 카카오 장소 검색으로 바로 찾고, 버스 정류장 위치는 공공데이터 키가 있을 때 노선 정류소 목록으로 찾음. 못 찾으면 남은 거리(버스 500m·지하철 1km)로 알림 |
| **안내 진동** | 화면이 꺼져도 계속 따라가며 손목만으로 구별되게: **좌회전 35m 전 짧게 2번 · 우회전 짧게 3번 · 유턴 4번 · 횡단보도·계단 길게 1번** (자전거는 70m 전, 그냥 직진으로 이어지는 구간은 진동 없음), 정류장·역 30m 앞 승차 알림(중간 2번), 내릴 곳 가까이 하차 알림(길게 3번), 내릴 정류장을 지나치면 아주 길게 2번 + 대중교통 경로 자동 재탐색, 경로 이탈 빠르게 5번(갈림길을 지나쳐 직진하면 30m 쯤에서), 도착 길게 1번. 진동은 '알람' 용도로 울려서 워치의 터치 진동을 꺼 두었거나 절전 모드·방해 금지 중에도 빠지지 않음. 안내는 지도가 다 뜨기 전에 바로 시작(지도 인증이 늦거나 실패해도 진동 안내·진행 중 아이콘은 됨) |

| **업데이트 버튼** | 앱을 열면 첫 화면 아래에 늘 **업데이트** 버튼(새 버전이 있으면 파란 **새 버전 업데이트**). 누르면 확인하고 곧바로 받아 설치 — 받는 동안 화면이 켜져 있음. 타일로 유튜브를 바로 열어도 맨 위에, 지도에선 위쪽 알림으로. 버전·최근 오류 기록 같은 앱 정보도 그 화면에 |
| **배터리** | 첫 화면 아래 동그란 **배터리** 버튼 → 배터리 기록 화면. 앱이 **15분마다** 잔량·전하량(µAh)·전압·온도·전류·화면 켜짐을 한 줄씩 적고(부팅 순간과 충전 시작도 — 충전 시작은 '충전 중' 조건 작업이 꽂고 몇 분 안에 잡는다), 그걸로 **1시간·8시간·24시간 소모율(%/h, 실측 mAh/h)**, 대기(화면 꺼짐) 소모율, 밤사이(00~07시), **판정**(정상·주의·비정상 — Android vitals 기준 4.44%/h 등), **잔량 표시 이상**(17%에서 꺼졌다 켜니 47% 같은 게이지 오류), **용량 추정**(충전 곡선으로 실제 만충 용량, 공칭 445mAh 대비 %), **실험**(비행기 모드·절전·시계만 사용 구간을 따로 계산), 요약 파일 쓰기. 화면이 꺼진 채 2시간 동안 시간당 5% 넘게 닳으면 알림(6시간에 한 번). 기록은 워치 안에만(30일) — 자세한 분석은 아래 **배터리 닥터** |

## 갤럭시 워치9 44mm가 이 앱을 감당하나요?

실제 워치(SM-L350, Wear OS 7 / Android 17)에 설치해서 지도·인증·내 위치 표시까지 확인했습니다.

| 항목 | 워치9 44mm | 이 앱에 필요한 것 | 판단 |
|---|---|---|---|
| 칩 | Snapdragon 5코어 3nm, GPU Adreno | 480×480 벡터 지도 그리기 | 여유 있음 (지도 SDK 가 'High spec' 으로 인식) |
| 메모리 | RAM 2GB | 지도 엔진 포함 수백 MB | 충분. 앱 정보 화면에서 실제 사용량 확인 가능 |
| 앱 실행 환경 | **32비트(armeabi-v7a)** — 실제 워치에서 확인 | 32비트용 지도 엔진 포함 | 업데이트 때는 32비트 전용 APK 만 받음 (처음 설치용 APK 엔 32·64비트 둘 다) |
| 위치 | 2주파 GPS(L1+L5), 지자기 나침반 | 도보 안내 정확도, 방향 표시 | 도심에서도 유리 |
| 배터리 | 445mAh | 화면과 GPS 가 가장 많이 씀 | **가장 큰 제약** → 아래 우회법 |

### 배터리 우회법 (기능은 그대로 두고 덜 쓰기)

- **필요한 순간에만 촘촘하게 위치 받기**: 화면을 볼 땐 1초. 손목을 내린 동안은 '다음에 할 일'(회전·횡단보도·승하차)까지 거리 기준으로 60m 안·이탈·출발 직후 1초, 250m 안 2초, 긴 직진 4초(8초까지 모아 받기), 신호·정류장에서 멈춰 있으면 갈림길 바로 앞이어도 5초, 버스에서 내릴 곳이 3km 넘게 15초 · 1.5km 넘게 10초(모아 받기), **지하철(지하)은 타는 동안·승강장에서 기다리는 동안 모두 GPS 대신 기지국·Wi-Fi 위치 10초**, 실내 출발로 1분 넘게 경로에 못 오르면 3초. 다른 앱이 GPS 를 1초마다 받아도 우리 앱은 계획한 간격보다 자주 깨지 않음. 화면을 다시 켜면 모아 둔 위치를 바로 받아 따라잡음.
- **기차·고속버스**: 역(터미널)에서 기다리는 동안 출발 3분 전까지 Wi-Fi·기지국 위치 30초. 타는 중엔 내릴 역이 10km 넘게·도착 10분 넘게 남았으면 **GPS 를 끄고 기지국·Wi-Fi 위치 1분**(KTX 안은 GPS 도 잘 안 잡힘, 중간 역 정차 중에도 그대로) → 4km·3분 전까지 GPS 10초 → 그 안 3초. 시간표보다 늦어지면 거리로만 판단. 역을 지나쳐 다음 역까지 가는 동안도 저전력.
- **배터리 15% 이하(충전 중 아님)**: 위치 간격을 두 배로(회전 앞도 2초) — 안내는 그대로.
- **폰 GPS 활용**: 워치가 폰과 연결돼 있으면 Wear OS 가 폰·워치 중 전력이 덜 드는 쪽 위치를 씀(시스템 기본 동작이라 따로 할 일 없음).
- **손목 내림 = 선만 그린 미니 지도**: 지도 엔진(GPU)·네트워크 없이 경로 좌표로 직접 그림. 화면의 85% 이상이 검정, 윤곽선만 사용(번인 방지 이동은 시스템이 함). 5초에 한 번, 또는 안내 단계가 바뀔 때만 다시 그림. 가려진 지도 배너는 그동안 고치지 않음.
- **도착 뒤**: 2분간 저전력 위치(Wi-Fi 위주), 그 뒤엔 다른 앱이 받은 위치만 얻어 쓰기(추가 전력 0), 5분 뒤엔 안내가 스스로 끝나 진행 중 아이콘·위치가 모두 꺼짐.
- **GPS 신호를 10초 넘게 못 받으면**(지하·실내) 배너에 'GPS 신호 약함'을 띄워 화면만 보고 기다리지 않게.
- **경로 밖에서 멈춰 있으면**(안내를 켠 채 카페·집에 들어감 등) 1초 GPS 대신 5초, 10분 넘으면 GPS 를 끄고 Wi-Fi·기지국 위치 15초 + 4분쯤마다 GPS 로 한 번(최대 30초) 확인해서 걷기 시작하면 바로 GPS 안내로. Wi-Fi·기지국 위치가 수십 m 튀는 것은 '걷기'로 보지 않음(멈춘 곳에서 오차보다 확실히 멀어져야 움직임). **경로를 벗어난 채 30분**이면 알림을 남기고 안내를 스스로 끝냄 — 출발 전 실내에서 기다리는 것, 버스·지하철 타는 중은 끝내지 않음.
- **경로 위에서 더 나아가지 않으면**(목적지 건물에 옆문으로 들어감·경로 위 카페) 10분 뒤 멈춰 있으면 GPS 대신 Wi-Fi·기지국 위치, **1시간** 진척이 없거나 걷는 안내에서 쓸 만한 위치를 **30분** 못 받으면 알리고 끝냄, 목적지 60m 안에서 3분 멈춰 있으면 도착으로 보고 끝냄. 위치가 안 와도 판단할 시각에 알람으로 깨움. **타려고 기다리는 동안**(시내 버스 정류장 30m 안·지하철 승강장·기차역)은 멈춤이 아님 — 정류장에선 실시간 도착을 계속 물으려고 5초 위치 그대로, GPS 가 한 번 튀어도 이어서 기다림. 정류장 옆에서 '안내 시작'만 누르고 잊었으면 **2시간** 뒤 끝냄(시간표가 있는 기차·고속버스는 빼고 — 놓치면 다음 편으로 다시 찾음). 다시 찾은 경로는 그 경로 기준으로 다시 셈.
- **앱이 꺼져 안내가 끊기면**(2GB 워치에서 동영상을 볼 때 등) 다음에 지도를 열 때(최근 앱·첫 화면으로 돌아와도) '안내가 끊겼어요'와 함께 그 목적지 길찾기를 다시 열어 줌(6시간 안, 한 번만 — 안내 시작은 사용자가). 도착했거나 끝낸 여정은 다시 열지 않음.
- **업데이트**: 새 버전 확인은 6시간마다·앱을 열 때 5분에 한 번, 어떤 연결에서든(1KB 도 안 됨). 내려받기·설치도 어디서나 — 밖에서는 폰 데이터를 씀(사용자가 그러기로 함). 폰 블루투스로 받다 끊기면 받은 데부터 이어받고(한 번에 3번까지 다시 잇기), '지금 업데이트'로 받는 동안엔 화면을 켜 둠(꺼지면 느린 블루투스 내려받기가 멈출 수 있음). 받은 파일이 update.json 과 계속 다르면(손상) 같은 릴리스는 자동으로 두 번까지만 받음(폰 데이터 낭비 방지 — '지금 업데이트'는 언제든). 자동 업데이트·설치가 실패한 까닭은 '최근 오류 기록'에 남음. 안내 중에는 설치를 미룸(설치하면 앱이 다시 시작되므로). 워치 CPU(32비트) 전용 APK 만, 코드까지 압축해서 받음 — 유튜브 재생 엔진(GeckoView)이 들어 있어 한 번에 **약 105MB**. 그래서 받을 때마다 **워치가 저장된 Wi-Fi 를 잠깐 켜 달라고 해서**(자동 10초·'지금 업데이트' 6초 기다림) 되면 그쪽으로 받음(블루투스보다 수십 배 빠르고 폰 데이터 안 씀, 다 받으면 바로 놓아줌). **자동 업데이트는 이렇게 큰 것을 워치 Wi-Fi 에서만 받고**(밖에서 폰 데이터로 매번 105MB 를 쓰지 않게, Wi-Fi 로 받다 끊기면 받은 데까지 두고 다음에 이어받기) **이틀 넘게 Wi-Fi 를 못 만나면 그때는 폰으로라도**(이틀은 처음 기다리기 시작한 때부터 — 릴리스가 잦아도 다시 세지 않음). '지금 업데이트'는 언제나 어디서든(Wi-Fi 가 없으면 폰 블루투스로, 끊기면 받은 데부터 이어받기). 설치하고 남은 APK 는 다음 확인 때 지움.
- **작은 업데이트(바뀐 부분만)**: 새 버전마다 CI 가 직전 릴리스 3개에서 오는 **패치**(`.kwdelta` — 바뀐 코드만, 보통 몇 MB)를 만들어 스스로 적용해 본 뒤 함께 올림. 워치는 깔린 APK 와 맞는 패치가 있으면 그것만 받아 **깔린 APK 로 새 APK 를 똑같이 다시 만들고**(SHA-256 을 update.json 과 대조, 다르면 설치하지 않음) 설치 — 폰 블루투스로도 금방이라 Wi-Fi 를 기다리지 않음. 패치가 깨졌거나 안 맞으면 전체 APK 로(그 패치는 다시 받지 않음), 받다 끊기면 받은 데까지 두고 다음에 이어받기. 업데이트 화면에 '1MB 미만 · 바뀐 부분만 받아요'처럼 실제로 받을 크기.

폰에서 지도를 그려 이미지로 보내는 방식도 검토했지만, 카카오 지도 SDK 는 폰 화면이 켜져 있어야 그릴 수 있고, 블루투스로 이미지를 계속 받는 데 워치 배터리가 더 들어서 쓰지 않았습니다.

### 배터리 닥터 — 워치9 배터리가 이상하게 빨리 닳을 때

이 앱과 상관없이 워치9 자체의 배터리 광탈(삼성멤버스에 2026년 9~10월 집중 제보: 시간당 5~6%, 12~17시간, 잔량 점프)을 **숫자로 밝히고, 루트 없이 막을 수 있는 건 막고, 서비스센터용 증거를 남기는** 도구. 설계·근거는 `docs/superpowers/specs/2026-10-19-battery-doctor-design.md`.

- **워치 쪽**: 위 '배터리' 화면(전용앱에 들어 있음, 따로 설치 없음).
- **PC 쪽 `battery-doctor`(Windows)**: 릴리스의 `battery-doctor.zip` 을 풀고 `BatteryDoctor.bat` 더블클릭. Android Studio 에 들어 있는 Java 와 adb 를 알아서 찾으므로 따로 설치할 게 없다. 메뉴: **연결**(워치 무선 디버깅 — 설정 › 워치 정보 › 소프트웨어 › 소프트웨어 버전 5번 탭 → 개발자 옵션) · **측정 시작**(`batterystats --reset`) · **수집·분석**(`dumpsys battery/batterystats/power/alarm/sensorservice/location/deviceidle/jobscheduler`, 설정, 패키지, 워치 CSV → 한국어 HTML 보고서: 화면 꺼진 동안 깨어 있던 비율, 범인 웨이크락·알람·센서, 앱별 추정 전력, 게이지 불일치, 판정 트리 설정 → 소프트웨어 → 게이지 → 하드웨어) · **차단 조치**(안전/주의/강함 등급, 항목별 선택, 전부 `data/journal.jsonl` 에 기록) · **되돌리기** · **증거 패키지**(보고서+원자료+신고문 3종: 삼성멤버스 오류 보내기, 서비스센터 접수 메모, 소비자분쟁해결기준 요구서 — 증상에 워치 15분 기록으로 대기 소모가 늘어난 때('10/16부터 시간당 1.0% → 2.5%')와 그 무렵 바뀐 것(워치 소프트웨어·앱 업데이트 등, 원인으로 단정하지 않음), 워치 기록의 켜짐(부팅) 시각(앞뒤에 '강제 재시작' 표시가 있었는지, 충전 안 하던 1~3% 다음 충전기에서 켜졌는지, 충전으로 오를 수 없을 만큼 잔량이 뛰었으면 '켜지기 5분 전 기록 17% → 켜진 뒤 47%', 방전 뒤 충전기에서 크게 올라 켜졌으면 '켜지기 40분 전 기록 2% · 충전기에서 켜짐 · 켜진 뒤 48%' — 본 그대로)·마지막 켜짐 전후 대기 소모·워치 앱이 본 단계(그 소견의 등급, 그 문제를 처음 짚은 때와 '그 뒤 워치가 두 번 이상 다시 켜졌는데도 계속' 등 — 지금은 안 보이는 문제도 처음·마지막으로 짚은 때)를, 시도한 조치에 워치에 남긴 '강제 재시작' 표시를 채워 '재시작해도 그대로'를 기억에 기대지 않고 남김 — 켜짐을 사용자가 한 재시작으로 적지는 않음; `share/` 는 이메일·좌표·일련번호를 가린 공유용).
- 측정 순서: 충전기에서 내린 뒤 **측정 시작** → 평소처럼(또는 실험 모드로) 반나절~하루 → 충전기에 올리기 **전에** 워치 Wi-Fi 를 켜고 **수집·분석**.
- **워치가 방금 짚은 것도 PC 가**: 수집할 때 워치 앱에 요약을 **지금 새로 쓰게** 하고(셸만 보낼 수 있는 신호), 워치가 최근 2시간 앱별 통계로 짚은 Play 서비스·One UI Watch 홈 과소모를 보고서 소견으로 가져온다 — Play 서비스면 자동 치료가 캐시 정리·Play 서비스 다시 시작을, 홈이면 강제 재시작이 먼저이고 재시작 뒤에도 또 나타났을 때만 '모든 앱 캐시 정리'(홈 캐시 삭제 단계를 대신)를 추천하며, 판정도 하드웨어 의심이 아니라 소프트웨어로. 전후 비교는 지난 수집 뒤 하루가 지나 쓴 요약만 견준다. 자동 치료가 캐시 정리·Play 서비스 다시 시작을 했으면 측정 시작 뒤 워치 앱에 **'치료함'**과 실제로 한 치료를 알려(셸만 보낼 수 있는 신호) 워치가 10분 뒤(다시 시작한 Play 서비스가 몰아서 하는 일을 빼고 — 배터리 화면을 열 때·수집 직전 요약을 쓸 때도) 앱별 기록을 새로 잰다 — 치료 10분 뒤 수집이 치료 전 기록으로 또 치료를 권하지 않고, 비정상 소모 판단도 치료 뒤로 다시 잰다(앱별 통계 권한이 없어도 — 그땐 요약이 알려진 문제는 못 본다며 메뉴 7 을 권함). 워치가 Play 서비스를 마지막 단계로 적었는데 또 치료했으면 요약이 그것으로 끝이 아니라고(업데이트·오류 보내기). 단계는 문제마다: Play 서비스를 다시 시작한 치료 뒤에도 또 나타나면 Play 서비스는 그다음 단계(업데이트·오류 보내기)로(같은 PC 치료를 또 권하지 않게), 홈은 캐시만 지워선 돌고 있는 홈이 그대로라 재시작해야 넘어간다. 워치가 홈 과소모(재시작 뒤에도 또)를 짚어 캐시 정리를 했으면 요약의 '다음:'이 **강제 재시작**부터, 그다음 단계면 이미 해 본 캐시 정리·재시작을 되풀이하지 않는다. Play 서비스 해결 순서도 워치와 같게(캐시 삭제 → 강제 재시작), 어시스턴트 업데이트 제거는 2023년 워치6 사례라고 적는다. 재시작·치료 직후에 수집하면 워치는 아직 다시 보는 중이라 문제 칸이 비지만, 이틀 안에 짚었던 문제를 요약에 몇 시간 전인지 적어(`seen_home_h`·`seen_gms_h`, 수집 때부터 셈) PC 가 보이고 — 그때가 이 보고서가 잰 구간(충전 뒤 통계·워치 기록 24시간까지 — 기록이 그보다 짧으면 그 길이) 안이면 '주의'로, 그 소모가 섞여 있어 그것만으로 **하드웨어로 단정하지 않는다**(할 일 맨 앞이 측정을 다시 시작해 하루 뒤 견주기). 그보다 앞이면 참고로만.
- **재시작 효과**: 시킨 대로 재시작했으면 그 뒤 대기 소모가 줄었는지 숫자로 — 재시작 직전의 대기 3시간(재시작 전 12시간 안에서 — 12시간 전체로 평균하면 재시작하게 만든 직전 한두 시간의 과소모가 묽어졌다)과 재시작 30분 뒤부터 12시간을 견줘 '재시작 뒤 대기 시간당 1.0% (그 전 4.0%) — 줄었습니다'(양쪽 2시간 넘게 쌓이면, 잔량 1% 계단 오차보다 클 때만 '줄었다/늘었다'). 재시작 뒤 이틀 동안, 권한 없이도 배터리 화면과 하루 요약에.
- 개인정보: 수집물은 PC 의 `data/` 에만 남고 어디로도 보내지 않는다. 남에게 보여 줄 땐 `share/` 폴더만.
- **잔량 표시 점검·게이지 보정(가짜 소모 잡기, 권한 불필요)**: "17%에서 꺼졌다 켜니 47%"는 배터리가 아니라 **잔량 게이지가 낮게 센 것**이라, 체감 소모의 일부는 가짜다. 워치가 화면 꺼진 채 쉬는 표본의 **전압으로 잔량을 어림잡아 표시 잔량과 비교**(12포인트 이상 의심, 20포인트 이상 확실)하고, 확실하면서 표시가 35% 아래면 **"잔량 표시가 N포인트 낮습니다 — 강제 재시작" 알림**(12시간에 한 번). 배터리 화면 '잔량 표시 점검'에 지금 오차·마지막 재시작 전후 잔량(+'강제 재시작 표시 남기기' 버튼)과 **게이지 보정 루틴**(완충+1시간 → 10% 아래까지 사용 → 다시 완충+1시간, 단계마다 알림, 끝나면 시작 때 오차와 지금 오차 비교). 전하량 계수기(mAh)보다 표시(%)가 더 빨리 줄면 '가짜 소모'로 따로 적는다. PC 보고서도 같은 소견(`gauge-drift`)으로 잔량 표시 문제를 판정한다.
- **배터리 사용 내역·알려진 문제·조치 효과**: 배터리 화면 '배터리 사용 내역 (24시간)'이 하루 소모를 **화면 켜진 동안 / 꺼진 대기**로 나누고(사용 통계로 화면 켜짐을 정확히 — 권한 주기 뒤), **가장 많이 닳은 시간 3개**를 그때 화면에 떠 있던 앱·뒤에서 돈 앱과 함께 보여 준다. 화면 밖에서 CPU 를 시간당 3분 넘게 쓰는 앱을 짚고, 2026년 갤럭시워치에 되풀이된 **Google Play 서비스 과소모**면 '알려진 문제'로 해결 순서(캐시 지우기 → 강제 재시작)와 앱 정보 바로 가기를 주고 비정상이면 알림. 2026년 9~10월 워치9·One UI 9 업데이트 뒤 보고된 **One UI Watch 홈 과소모**(배터리 1위가 홈, 보통 재시작으론 안 풀리고 강제 재시작으로 나아짐)도 — 홈은 화면을 그리는 프로세스라 앱별 등급(화면에 떠 있던 시간 기준)으론 매기지 않고, 사용 통계로 본 화면 켜짐 시간의 절반·받은 알림 하나에 2초를 빼고 남은 CPU 가 시간당 5분(10분이면 알림) 넘을 때만(화면이 창의 30% 넘게 켜져 있었거나 화면 시간을 모르면 짚지 않음). 알려진 문제는 모두 기록이 1시간쯤(55분) 쌓였을 때만 본다. 재시작은 부팅 번호로 알아채 그 앞의 기록은 보지 않고(켜진 지 10분 지난 첫 기록을 기준값으로만 — 부팅 직후 몰리는 동기화를 판단에 넣지 않고, 강제 재시작으로 통계 일부가 사라져도, 이 버전으로 업데이트하자마자 재시작해도 엉뚱한 과소모로 짚지 않음, 타일 줄도 바로 내림) 시킨 대로 재시작했는데 계속 '재시작'이라 하지 않음. 재시작한 뒤에도 같은 문제가 또 나타나면(이틀 안) 같은 말을 되풀이하지 않고 **다음 단계**로 — 홈은 홈 앱 캐시 삭제 → 한 번 더 강제 재시작(타일 'One UI Watch 홈 과소모 — 홈 캐시 지우고 재시작', 할 일 '재시작 뒤에도 홈 과소모'), Play 서비스는 캐시(아직이면) → PC 툴킷 자동 치료(PC 보고서도 Play 서비스를 짚으면), 비정상이면 12시간 쉬는 중이어도 그 소식은 한 번 알림. 그 다음 단계를 보인 뒤 또 재시작했는데도(Play 서비스는 PC 치료가 Play 서비스를 다시 시작한 뒤에도) 계속되면 **마지막 단계**로 — 사용자가 할 일이 거의 남지 않아 같은 '캐시 지우고 재시작'을 되풀이하지 않고 오류 보내기(삼성 안내 그대로: 폰의 Galaxy Wearable 앱 › 대시보드 › ⋮ › 설정 › 문의하기 › 오류 보내기 또는 Samsung Members › 도움 받기 › 질문/오류 보내기 › 보내기 › 오류 보내기, 기기는 워치로, '시스템 로그 데이터 보내기' 체크, 증상 2~3분 안 — 과소모가 이어지는 동안. PC 툴킷의 할 일·신고문도 같은 길)·워치 소프트웨어 업데이트(폰 Galaxy Wearable 앱 › 워치 설정 › 워치 소프트웨어 업데이트)·Play 스토어 모두 업데이트(충전 중 — 도움이 됐다는 보고)·밤엔 지킴이 밤 모드(초기화는 마지막 수단), 알림은 하루에 한 번(타일 '… 계속 — 오류 보내기'), 앱 정보로 할 일이 없으면 그 바로 가기는 빼고. 단계는 문제마다 그 단계를 처음 보인 부팅(Play 서비스는 그때까지의 PC 치료 횟수도)을 적어 두고 넘긴다(재시작을 연달아 했다고 건너뛰지 않고, 시계가 뒤로 가도·앱별 통계 파일이 사라져도 이어짐, 이전 버전에서 시작된 일은 PC 치료를 재시작으로 읽지 않음). 비정상 소모 알림은 지금 다시 짚은 비정상 문제가 있을 때만 '재시작·치료 뒤에도 또 나타난 문제 — 배터리 화면 맨 위 지금 할 일'을 말하고(재시작으로 사라진 뒤의 과소모엔 하지 않음), 비정상 모드 중에 재시작(부팅 기록이 늦거나 빠져도 지킴이가 15분 기록마다 부팅을 적어 알아채고 켜진 때부터 — '강제 재시작 표시'처럼 재시작 직전에 남은 잔량은 출발점으로 쓰지 않음)하거나 PC 치료(앱별 통계 권한이 없어도)를 하면 그 모드를 풀고 그 뒤로 다시 잰다(1시간 45분이 쌓여야 — 그 앞의 과소모로 다시 절전을 켜지 않게, 부팅 때 게이지가 다시 잰 잔량은 출발점으로 쓰지 않음). 알려진 문제 알림은 문제마다 따로(서로 덮어쓰지 않게). Play 서비스의 첫 단계는 캐시 삭제 뒤 바로 강제 재시작(최근 2시간으로 보는 판단이라 '30분 뒤 그대로면'은 쓸데없는 재시작을 시켰다). 앱별 칸이 비었거나 짧으면 왜인지(재시작 뒤 다시 모으는 중 등)와 언제부터 보이는지 적고, 1시간이 안 되는 창에선 앱마다 등급·시간당 표시 없이 그동안 쓴 만큼만(재시작 직후 동기화가 '비정상'으로 빨갛게 보이지 않게). 하루 요약의 `[홈]` 줄이 이 워치에서 홈을 따로 셀 수 있는지(uid) 보여 주고, 홈이 시스템 uid 를 같이 쓰면 PC 보고서도 '홈만 따로 셀 수 없음'(그땐 워치의 배터리 사용량 화면을 직접)이라고 알린다. 밤새 화면을 안 켰어도 하루치 기록으로 '켜진 적 없음'을 알아 아침에 사라지지 않음. 공유 uid 묶음은 홈·Play 서비스 이름으로 부르고, 처음 보인 이름은 그 구간엔 기준값만(묶음 이름이 바뀌어 충전 뒤 누적이 한 구간에 잡혀 엉뚱한 과소모로 짚지 않게). 배터리 사용량 1위가 홈이라는 것만으로는 고장이라 단정할 수 없음. 알림이 화면을 많이 켜면(하루 50번+) 삼성 안내대로 **웨어러블 앱 › 워치 설정 › 알림 › 고급 설정 › '알림 받으면 화면 켜기' 끄기**(알림은 그대로 옴)를 할 일로('알림 화면 켜짐 N번 · 하루 X%'), 같은 곳의 '알림 수신 8초 내 확인 시 상세 내용 바로보기'도 끄라고(삼성 배터리 안내). 지킴이의 밤 모드가 켜진 밤과 아닌 밤의 소모를 비교해 **실제로 몇 % 줄였는지** 보여 준다. 지킴이 판단은 최근 3일 기록만 읽고(파일 끝부분만), 화면 켜짐은 사용 통계로 정확히 본다. PC 툴킷: Play 서비스가 짚이면 자동 치료가 **모든 앱 캐시 정리(pm trim-caches)와 Play 서비스 다시 시작**을 함께 한다.
- **타일 '배터리'**: 워치 화면을 옆으로 넘기면 잔량 · 최근 소모율과 판정 · **언제 15%·0%**('내일 15% 새벽 3:24 · 0% 오전 7:40') · 지킴이 상태(알려진 문제가 있으면 그 할 일, 잔량 표시가 어긋나면 '잔량 표시가 25포인트 낮음 — 실제론 더 남음')가 한눈에. 충전 중엔 제목이 '충전 중 N%', 소모율 대신 **하루 평균**(방전이 3시간 이상 쌓였을 때). 글은 띄어쓰기에서만 줄이 바뀌고(타일은 시스템이 그려 한글이 '않습/니다'처럼 갈라졌다 — 보이지 않는 결합 문자로 막음), 이 줄들을 이제 읽어 주기(TalkBack)도 읽는다(가운뎃점·줄표는 쉼표로). 글이 쓸 수 있는 폭(화면 폭 ÷ 글꼴 배율)이 200dp 보다 좁으면(작은 워치·큰 글꼴) 예상은 '0% 내일 오전 7:40' 한 줄·소모율은 작은 글씨로. 44mm·40mm·작은 원형(200·199·192·186dp)·글꼴 1.15~1.3배·예전 렌더러에서 잘림·가림 없이 들어가는지 타일 렌더러로 실제로 그려 시험(`BatteryTileFitTest`). 15분 기록마다 새로 그리고(보일 때만), '자세히'를 누르면 배터리 화면. 배터리 화면 맨 위에도 같은 '지금 페이스' 줄.
- **배터리 지킴이(워치가 스스로 막기)**: PC 툴킷 메뉴 **7 권한 주기**(`pm grant` 로 BATTERY_STATS·WRITE_SECURE_SETTINGS 등 개발용 권한)를 한 번 하면 배터리 화면의 '배터리 지킴이'가 살아난다 — 밤(00~07시) 화면이 30분 넘게 꺼져 있으면 **절전 모드+AOD 끔**(옵션: 위치·계정 동기화) 후 아침·충전·기상 때 원래대로, 화면 꺼진 채 2시간 동안 시간당 5% 넘게 새면 **즉시 절전 + 범인 앱 알림**('앱 정보'·'되돌리기' 버튼), 잠자기 전 아침까지 못 버틸 것 같으면 **"N분 충전" 알림**, '앱별 소모(최근 2시간)'에 웨이크락·CPU·센서·GPS 순위(이 앱 포함). 절전을 손수 끄면 12시간 쉰다. 메뉴 **8 자동 치료**는 권한 주기 → 수집·분석 → 범인 앱 백그라운드 제한·위험 설정 끄기 → 통계 초기화를 한 번에(전부 `undo --all` 로 되돌림). 시계가 뒤로 가 지난 시각이 '미래'가 돼도 알림 쉼·비정상 절전(6시간)·기록 정리가 그만큼 멈추지 않고, 타일 잔량도 미래 시각의 묵은 기록으로 보이지 않는다.
- **밤 모드에 화면 켜기 제스처까지**: 밤 모드가 **손목 올림·화면 터치로 켜지는 것**도 끈다(기본 켬 — 삼성 취침 모드와 같은 묶음, 버튼으로는 켜짐, 아침·충전·기상 때 원래대로). **'Hey Google' 음성 호출 끄기**는 고른 사람만. 아침에 화면을 본 것은 사용 통계로도 알아채 밤 모드를 바로 끝낸다. 키는 AOSP Wear OS 의 `global/ambient_tilt_to_wake`·`ambient_touch_to_wake`·`hotword_detection_enabled` — 이 워치에 있을 때만 바꾸고, 이미 꺼진 것은 건드리지 않는다.
- **PC 없이 권한 주기**: PC 가 없으면 폰의 ADB 앱(예: Bugjaeger)으로 워치 무선 디버깅에 연결해 셸에 `pm grant com.mywatch.kakaomap android.permission.BATTERY_STATS` · `pm grant com.mywatch.kakaomap android.permission.WRITE_SECURE_SETTINGS` · `appops set com.mywatch.kakaomap GET_USAGE_STATS allow` 세 줄(배터리 화면에도 나옴). 되돌리기는 `pm revoke …` / `appops set … default`.
- **레버 점검**: 배터리 화면 지킴이 칸에 레버마다 **이 워치에서 듣는지**(설정 키가 있는지·권한·지금 값). 같은 내용이 요약 파일의 `[레버 점검]` 줄로 PC 툴킷 보고서에 들어간다.
- **24시간 그래프**: 배터리 화면 맨 위 쪽에 하루 잔량 선(기록이 빠진 곳은 끊김) · 충전(초록) · 가장 많이 닳은 시간(빨강) · 화면 켜짐 띠(노랑, 사용 통계가 있을 때) · 6시간마다 시각. 화면 낭독기는 '24시간 동안 96% → 35% · 충전 1번 · 가장 많이 닳은 때 오후 12시'처럼 읽는다.
- **시계 화면 점검**: 지금 시계 화면 이름을 보여 주고, **타사 시계 화면**이 웨이크락·CPU 를 많이 쓰면 '알려진 문제'로 짚어 **기본 삼성 시계 화면으로 바꿔 하루 비교**·정보 칸과 초침 줄이기를 안내(삼성·구글 기본 화면, Watch Face Format 렌더러는 제외).
- **충전 습관(배터리 수명)**: 최근 7일 충전 횟수, **100%로 충전기에 머문 시간**(하루 2시간 넘으면 설정 › 배터리 › **배터리 보호**(90%에서 멈춤) 권함 — 이미 켜져 있으면 알아챔), 충전 중 최고 온도(42℃ 넘으면 안내). **충전 속도**: 충전마다 처음 오른 10~85% 구간 빠르기로 완충 시간을 어림해(뒤쪽은 원래 느려 실제는 더 걸림, 배터리 보호로 머문 시간은 빼고) 그 가운데 값(아래쪽)이 삼성 공식(고속 충전 — 워치9 40mm 80분·44mm 90분)의 1.3배 이상이고 잰 충전이 두 번 이상이면 '충전이 느림'(둘이면 둘 다 느려야) — 느린 충전들이 대개 40℃ 이상이었으면 워치9에 많이 보고된 열로 느려지는 모습이라 서늘한 곳·케이스 빼기·작은 선풍기 바람(한 사용자: 15→100% 2시간 10분 → 1시간 15분, 얼음은 습기 때문에 쓰지 않기)을, 아니면 들어 있던 충전기·어댑터(워치8 충전기·타사 거치대는 느리거나 안 된다는 보고)·충전기 윗면과 워치 뒷면 닦기를. PC 보고서(`watch-charge-slow`)와 신고문에도 '충전 속도: 완충 어림 2시간 47분 넘게 — 삼성 공식(고속 충전) 44mm 90분, 최근 7일 충전 N번 중 M번을 잼, 사용한 충전기: [  ]'(요구서 하자 내용엔 충전 중 뜨거웠을 때만). 충전 중(충전 시작 작업이 10분마다 봄) 42℃ 이상이고 80% 아래면 그 자리에서 '충전 중 43℃ — 충전이 느려질 수 있음'(식히는 길) 알림을 충전마다 한 번, 같은 안내는 사흘에 한 번(2℃ 넘게 더 뜨거우면 다시), 밤엔 소리 없이, 빼면 거둠. 켜진 뒤 처음 남는 15분·충전 시작 기록이 부팅 기록이 되어(부팅 작업이 늦게 돌아도) '방전 뒤 충전기에서 켜니 48%' 같은 잔량 점프를 놓치지 않음.

### 2) 워치에 설치 — ✅ 완료 (컴퓨터에서 무선 디버깅으로)

다시 설치해야 할 때(새 워치 등):
1. 워치 **설정 > 워치 정보 > 소프트웨어 정보 > 소프트웨어 버전** 5~7번 톡 → 개발자 옵션
2. **개발자 옵션 > ADB 디버깅 ON, 무선 디버깅 ON** → **새 기기와 페어링** 의 IP:포트·코드로 `adb pair`, 무선 디버깅 화면의 IP:포트로 `adb connect`
3. `adb install -r -g kakao-watch-map.apk` (‑g: 위치·알림 권한 미리 허용)
4. `adb shell appops set com.mywatch.kakaomap REQUEST_INSTALL_PACKAGES allow` (앱이 스스로 업데이트하게)

바로 받으려면 앱을 열고 첫 화면 아래 **업데이트**(새 버전이 있으면 파란 **새 버전 업데이트**) 한 번 — 확인하고 바로 받아 설치하며, 받는 동안 화면이 켜져 있습니다.
설치 전에 ① SHA-256 ② 패키지명 ③ 버전이 더 높은지 ④ 지금 앱과 같은 서명 키인지 확인하고, 하나라도 틀리면 설치하지 않습니다.
앱이 스스로를 업데이트하므로(설치 주체 = 앱 자신) 워치에서 확인 버튼을 누를 필요가 없습니다.

### 5) 유튜브 API 키 — 인기 차트·검색·채널·재생목록 — ✅ 완료

유튜브 화면의 목록(인기 음악·인기 동영상·검색·채널·재생목록)은 무료 YouTube Data API 키로 받습니다(하루 1만 단위, 그중 검색은 약 100번). 키를 바꿔야 할 때:

1. [Google Cloud 콘솔](https://console.cloud.google.com) 로그인 → 위쪽에서 프로젝트 선택(없으면 **새 프로젝트**)
2. **API 및 서비스 > 라이브러리** → `YouTube Data API v3` 검색 → **사용**
3. **API 및 서비스 > 사용자 인증 정보** → **+ 사용자 인증 정보 만들기 > API 키** → 키 복사
4. (권장) 만든 키 **수정** → **API 제한사항: 키 제한 → YouTube Data API v3** 만 체크 → 저장. 이게 핵심 — 공개 APK 에서 누가 키를 꺼내 써도 유튜브 한도만 줄고(돈이 나가지 않음), 검색 한도를 다 쓰면 앱은 그날 카카오 검색으로 넘어감.
   덤으로 **애플리케이션 제한사항: Android 앱** → 패키지 `com.mywatch.kakaomap`, SHA-1 `2D:B3:DE:4F:C3:E9:9A:A5:67:E3:78:7E:EC:A1:81:A4:AA:C6:09:CA` 도 넣을 수 있음 (앱이 이 두 값을 요청에 붙여 보냄 — 다만 둘 다 공개된 값이라 흉내 낼 수는 있음)
5. GitHub 저장소 **Settings > Secrets and variables > Actions > New repository secret** — 이름 `YOUTUBE_API_KEY`, 값에 붙여넣기
6. Claude 에게 말하거나 Actions 에서 **Build & release > Run workflow** → 다음 업데이트부터. 배포할 때마다 키가 되는지 확인해 실행 요약에 **유튜브 키 확인** 알림(되면)이나 경고(안 되면, 까닭과 함께)가 뜸. **YouTube API check** 워크플로는 실제 API 가 앱이 기대하는 모양 그대로 대답하는지까지 확인

### 6) 재생 화면 올리기 (GitHub Pages) — ✅ 완료

`web/` 이 `main` 에 올라가면 Actions 의 **Watch player page** 가 시뮬레이터로 확인한 뒤 `gh-pages` 브랜치로 올리고, GitHub Pages 가 `https://<사용자>.github.io/<저장소>/tube/`(재생 화면)·`/privacy.html`(개인정보 처리방침)·`/`(앱 소개)로 보여 줍니다. GitHub Pages 가 꺼져 있으면 한 번만: 저장소 **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `gh-pages` / (root) → Save**. 재생 화면에 닿지 못하면 앱은 알아서 폰 유튜브로 틉니다. 앱 안 엔진이 멈췄을 때를 위해 워치에 **삼성 인터넷**이 있으면 좋습니다(없으면 그때도 폰으로).

### 7) 유튜브 로그인 켜기 — 구독·좋아요·내 재생목록 (10분)

로그인 없이도 검색·인기·채널·재생목록·재생은 다 됩니다. 내 구독·좋아요·재생목록을 워치에서 보려면 구글 로그인 클라이언트를 한 번 만듭니다(무료).

1. [Google Cloud 콘솔](https://console.cloud.google.com) — **유튜브 API 키를 만든 그 프로젝트**를 선택
2. **Google 인증 플랫폼(Google Auth Platform)** → 처음이면 **시작하기**: 앱 이름 `갤럭시워치 전용앱`('YouTube'·'Google' 같은 이름은 넣지 않기 — 구글·유튜브 브랜드 규칙), 사용자 지원 이메일, **대상: 외부**, 연락처 이메일 → 만들기
3. **브랜딩(Branding)** — 게시하려면 먼저 채워야 합니다(웹 페이지가 GitHub Pages 에 올라간 뒤): 애플리케이션 홈페이지 `https://<사용자>.github.io/<저장소>/`, 개인정보처리방침 링크·서비스 약관 링크 `https://<사용자>.github.io/<저장소>/privacy.html`, **승인된 도메인** `<사용자>.github.io` → 저장. 로고는 넣지 않기(넣으면 구글 검증을 받아야 함). 그다음 **대상(Audience)** → **앱 게시 → 확인**(프로덕션) — '테스트' 상태로 두면 구글이 7일마다 로그인을 풀어 버립니다. 검증은 받지 않아도 됩니다(나 혼자 쓰는 앱 — 로그인할 때 '확인되지 않은 앱' 화면이 한 번 나오면 **고급 → (앱 이름)(으)로 이동**)
4. **데이터 액세스** → **범위 추가 또는 삭제** → `https://www.googleapis.com/auth/youtube.readonly` 체크 → 업데이트 → 저장
5. **클라이언트** → **+ 클라이언트 만들기** → 애플리케이션 유형 **TV 및 입력 제한 기기** → 이름 아무거나 → 만들기 → **클라이언트 ID**·**클라이언트 보안 비밀번호** 복사 (비밀번호는 만들 때 뜨는 창에서만 다 보입니다. 놓쳤으면 그 클라이언트 → 오른쪽 위 ⓘ → '클라이언트 보안 비밀번호' 옆 복사 버튼, 별표째로 복사되면 **+ Add secret** 으로 새로 만들기)
6. GitHub 저장소 **Settings > Secrets and variables > Actions** 에 두 개: `YOUTUBE_OAUTH_CLIENT_ID`, `YOUTUBE_OAUTH_CLIENT_SECRET`
7. 다음 배포부터 워치의 **유튜브 › 로그인**이 켜집니다. 배포할 때마다 실행 요약에 **유튜브 로그인 확인**(코드를 받아 토큰을 한 번 물어 ID·비밀이 맞는지) — 사람이 할 일 없이 확인

## 알아 둘 한계 (솔직하게)

- **기차·고속·시외버스는 시간표입니다**(공공데이터 TAGO). 지연·운휴·매진은 반영되지 않고, 열차 위치·지연 실시간 정보는 공개 API가 없습니다. 시간표에 KTX 가 빠진 날은 다음 주 같은 요일 시간표로 채우므로 그날만 다른 열차는 틀릴 수 있습니다(목록에 표시).
- 역·터미널은 카카오 장소 이름과 TAGO 이름을 맞춰 찾으므로(서관·동관, '부산서부'↔'부산사상' 같은 이름 차이는 처리) 작은 정류소나 이름이 많이 다른 터미널은 빠질 수 있습니다. 같은 이름에 TAGO 번호가 여럿인 터미널은 첫 번호만 봅니다.
- 선로·고속도로 모양을 몰라 **지도에는 역과 역을 직선으로** 그립니다.
- 실시간 버스 도착은 TAGO 가 지원하는 지역만 나옵니다. 서울·경기는 별도 시스템이라 정보가 비거나 일부만 나올 수 있습니다.
- 지하에서는 GPS가 안 잡혀서 **지하철 하차 진동은 지상 구간에서만** 동작합니다. 버스는 내릴 정류장 약 500m(짧은 구간은 절반) 전에 알립니다.
- 카카오 REST 키는 APK 안에 들어 있어서, 공개 저장소의 APK를 분석하면 꺼낼 수 있습니다. 결제(월렛)를 연결하지 않았다면 돈이 나가지는 않고 최악의 경우 하루 무료 한도가 소진됩니다. 이상하면 키를 새로 발급해 GitHub Secret `KAKAO_REST_API_KEY` 로 넣으면 다음 빌드부터 바뀝니다.
- **프리미엄은 앱 안 재생 화면에 적용되지 않습니다.** 재생은 유튜브 공식 플레이어(임베드)로 하는데, 임베드 플레이어는 유튜브 정책상 내 계정으로 로그인해 재생할 수 없어 광고가 나올 수 있습니다. 이 앱의 구글 로그인은 구독·좋아요·재생목록을 '보기'만 하는 권한이라 재생과는 상관없습니다. 광고 없이 보려면 길게 눌러 **폰 유튜브에서 보기**(폰의 유튜브 앱 = 내 프리미엄 계정). 다른 앱이 유튜브 영상·소리를 직접 받아 재생하는 건 유튜브 약관 위반이라 하지 않습니다.
- **화면이 꺼지면 멈춥니다.** 유튜브 규칙(보이지 않는 플레이어로 틀지 않기 — 개발자 정책 III.I.9)이라 화면이 꺼지면 소리도 멈춥니다. 재생하는 동안 화면을 켜 두므로 배터리를 꽤 씁니다 — 손대지 않고 **2분이면 화면을 어둡게**(밝기만, 플레이어를 덮지 않음 · Shorts 는 그대로), **45분이면 멈춤**(잊고 둔 재생·한 곡 반복·믹스 이어 듣기), 손대면 다시 밝게. 재생 화면의 잠자기 타이머로 더 줄일 수 있음. 올린 사람이 다른 곳 재생을 막아 둔 동영상·연령 제한 동영상은 워치에서 못 틀어 폰으로 보냅니다. 처음 한 번은 플레이어 가운데 ▶를 눌러야 할 수 있습니다(소리 자동 재생 막기). 소리는 워치 스피커나 워치에 연결한 이어폰으로.
- 유튜브 API 로는 내 계정의 **홈 추천**을 받을 수 없어서(공식적으로 막힘) 홈 '전체'는 **유튜브 믹스가 고른 동영상**(이 앱에서 믹스로 튼 것마다 공식 플레이어가 정한 다음 동영상들 — 문서에 있는 `getPlaylist()`) · 구독 새 동영상 · 이 앱에서 본 채널 · 인기 차트를 워치 안에서 섞어 만듭니다. 그래서 처음엔 인기 차트 위주이고, 동영상을 볼수록 내 취향의 믹스가 늘어납니다. 유튜브의 인기 차트(API)는 2025년 7월부터 음악·영화·게임 차트에서 나오고, 뉴스는 '뉴스' 분류 차트로 받습니다.
- **Shorts** 는 유튜브 API 에 'Shorts' 표시가 없어 세로 화면·3분 이하로 가려 내고, 채널의 Shorts 목록은 유튜브가 자동으로 만드는 목록(`UUSH…`, 문서에 없음 — 바뀌면 일반 업로드로 대신)을 씁니다. 유튜브 로고·Shorts 로고는 쓰지 않습니다(브랜드 규칙).
- 유튜브 검색은 하루 약 100번(무료 한도)입니다. 같은 검색은 3시간 동안 기억하고, 한도를 다 쓰면 그날은 카카오 동영상 검색(유튜브 영상 일부만)으로 찾습니다. 없으면 '폰 유튜브에서 이 검색 열기'.
- 로그인 클라이언트는 구글 검증을 받지 않은 '확인되지 않은 앱'(프로덕션)이라 로그인할 때 경고 화면이 한 번 나올 수 있고, 이런 앱으로 로그인할 수 있는 사람은 평생 100명까지입니다(혼자 쓰기엔 충분).
- 지도(카메라) 회전 방향은 앱이 화면 좌표로 확인해 스스로 맞춥니다(`location/MapTurn.kt`). 부채꼴만 반대로 돌면 `AppConfig.HEADING_SIGN` 을 `-1` 로 바꾸면 됩니다(말씀만 하시면 고쳐 드립니다).
- 카카오맵 SDK 는 ARM 전용이라 PC의 x86 에뮬레이터에서는 지도가 안 뜹니다. 실제 워치로 테스트하세요.
